# 1. 프로젝트 소개

## 발표 제목

**AI Vision 기반 PCB 품질 판별 및 AGV 연계 스마트 MES**

부제:
> PCB 입고·검사계획부터 AI 불량검사, 작업자 검수, AGV 이송, 재고 연계, 품질 분석까지 통합한 스마트 제조 관리 시스템

## 한 줄 소개

본 프로젝트는 PCB 이미지를 YOLO 기반 AI 모델로 검사하고, 검사 결과에 따라 작업자가 최종 판정한 뒤 AGV 상태전이와 재고·품질 분석까지 연결하는 스마트 MES입니다.

## 프로젝트 핵심 목표

기존 제조 현장은 다음과 같은 문제를 가지고 있습니다.

- 육안 검사에 따른 작업자 피로와 판정 편차
- 검사·물류·재고 시스템이 분리되어 발생하는 정보 단절
- 불량 발생 위치와 유형을 장기적으로 분석하기 어려움
- 생산 및 검사 현황을 실시간으로 파악하기 어려움
- 검사 결과가 후속 공정에 자동으로 연결되지 않음

이 프로젝트는 이러한 문제를 해결하기 위해 다음 기능을 하나의 시스템으로 통합했습니다.

- PCB 검사계획 및 입고 배치 관리
- YOLO 기반 PCB 불량 검출
- 실시간 검사 진행 모니터링
- 작업자 최종 검수
- AGV 이송 및 버퍼 관리 시뮬레이션
- BOM 기반 재고 소요량 계산
- AI 판정 정확도 및 불량 패턴 분석
- MES 데이터 기반 챗봇

# 3. 전체 작동 원리

```
검사계획 등록
    ↓
입고 PCB 배치 생성
    ↓
라인 배정 또는 Waiting Area 대기
    ↓
AGV가 배치를 검사 라인으로 이송
    ↓
YOLO 기반 PCB 이미지 검사
    ↓
검사 결과와 Bounding Box 저장
    ↓
불량 Detection 작업자 검수
    ↓
배치 최종 품질 판정
    ↓
검사 후 BUFFER 이송
    ↓
정상 PCB의 BOM·재고 확인
    ↓
최종 적재 또는 SMD 공정 인계
    ↓
품질 데이터 분석 및 리포트 생성
```

## 1단계: 검사계획 등록

사용자는 검사 예정일, PCB 모델, 검사 수량, 대상 라인을 선택합니다.

등록된 계획은 `PLANNED` 상태가 되며 다음 정보가 저장됩니다.

- 검사계획 코드
- 검사 예정일
- PCB 모델
- 검사 수량
- 대상 검사 라인
- 계획 상태

계획을 취소할 때는 실제 데이터를 삭제하지 않고 `CANCELLED` 상태로 변경하는 소프트 취소 방식을 사용합니다.

## 2단계: 입고 배치 생성

검사계획을 기준으로 입고 배치를 생성합니다.

이 과정에서:

- `production_batch`가 생성됩니다.
- 계획 수량만큼 `batched_pcb`가 생성됩니다.
- 각 PCB에 검사할 원본 이미지가 연결됩니다.
- 배치 코드가 발급됩니다.
- 계획은 `BATCH_CREATED` 상태로 변경됩니다.

같은 라인에 이미 검사 중인 배치가 있다면 새 배치는 Waiting Area에서 대기합니다.

라인당 다음 규칙을 적용합니다.

- 현재 작업 배치: 최대 1개
- 대기 배치: 최대 1개
- 다른 PCB 모델이 사용 중인 라인에는 배치 등록 제한
- 대기 슬롯이 찬 경우 추가 배치 등록 제한

## 3단계: AGV 라인 이송

라인이 비어 있는 경우 배치는 `LINE_ASSIGNED` 상태로 전환되고 AGV가 배치를 라인으로 운반합니다.

물류 위치는 다음과 같이 변경됩니다.

```
WAITING_AREA
    ↓
TO_LINE
    ↓
LINE
```

AGV는 실제 하드웨어를 제어하지 않고 화면과 백엔드 상태전이를 기반으로 시뮬레이션됩니다.

- 총 8개 검사 라인
- 총 12대 AGV
- 라인별 전담 AGV와 권역별 지원 AGV
- 충전 구역 및 Waiting Zone
- AGV 간 안전거리 고려
- 배터리 부족 시 충전 우선
- 진행 중 이송 상태 복원

## 4단계: YOLO 불량검사

검사 시작 시 배치는 다음 상태로 변경됩니다.

```
LINE_ASSIGNED → INSPECTING → INSPECTED
```

PCB는 배치 내 순번대로 한 장씩 검사됩니다.

고해상도 PCB 이미지의 작은 불량을 놓치지 않도록 전체 이미지를 고정된 3×3, 총 9개 타일로 분할합니다.

```
원본 PCB 이미지
    ↓
3×3 타일 분할
    ↓
각 타일 YOLO 추론
    ↓
Bounding Box 좌표를 원본 기준으로 복원
    ↓
겹치는 동일 클래스 Detection 병합
    ↓
최종 검사 결과 저장
```

저장되는 주요 결과는 다음과 같습니다.

- 정상·불량 여부
- AI 불량 유형
- 신뢰도
- Bounding Box 좌표
- 추론 시간
- TP, TN, FP, FN 평가값
- 검사 시각
- 모델 관련 메타데이터

실제 실행에서는 YOLO 모델을 PCB마다 다시 로딩하지 않습니다. 별도 worker process가 모델을 한 번 로드하고 반복해서 재사용하도록 설계하여 추론 오버헤드를 줄였습니다.

## 5단계: 실시간 화면 반영

검사가 시작되면 검사 전용 WebSocket을 통해 진행 이벤트를 전송합니다.

대표 이벤트는 다음과 같습니다.

- 배치 검사 시작
- PCB 검사 시작
- PCB 검사 완료
- 검사 진행률 변경
- 배치 검사 완료
- 검사 실패

프론트엔드는 이벤트를 수신해 다음 정보를 갱신합니다.

- 현재 검사 중인 PCB
- 완료 PCB 수
- 전체 진행률
- 정상·불량 여부
- 검출 불량 유형
- 신뢰도
- WebSocket 연결 상태

## 6단계: 작업자 최종 검수

AI가 불량을 검출하면 `defect_review` 데이터가 `PENDING` 상태로 생성됩니다.

작업자는 각 Detection에 대해 다음 작업을 수행할 수 있습니다.

- AI 판정 승인
- 불량 유형 수정 후 승인
- 오탐 처리
- 여러 건 일괄 승인

상태는 다음과 같이 변경됩니다.

```
PENDING
 ├─ CONFIRMED_DEFECT
 └─ FALSE_ALARM
```

모든 검수가 완료되면 배치의 최종 품질 판정을 잠급니다.

- 확정 불량이 하나라도 존재: `DEFECT`
- 확정 불량이 없음: `NORMAL`

최종 판정이 잠긴 이후에는 작업자가 판정을 다시 변경할 수 없도록 해 데이터 일관성을 유지합니다.

## 7단계: 검사 후 AGV 이송

검사가 완료되면 AGV가 배치를 검사 후 버퍼로 이동시킵니다.

```
LINE
   ↓
TO_POST_INSPECTION_BUFFER
   ↓
POST_INSPECTION_BUFFER
   ↓
TO_FINAL_DOCK
   ↓
FINAL_DOCK
```

검사 후 버퍼는 16개의 슬롯으로 관리됩니다.

- `EMPTY`: 비어 있음
- `RESERVED`: 이송 중인 배치가 예약
- `OCCUPIED`: 배치가 도착함

버퍼가 가득 차면 배치는 라인에서 대기합니다. 버퍼로 이송이 완료되어 라인이 비워지면 Waiting Area에 있던 다음 배치를 자동으로 승격합니다.

모든 검수가 끝나 최종 판정이 확정된 배치는 최종 적재 구역으로 이동하고 `COMPLETED` 상태가 됩니다.

## 8단계: 재고 및 후속 공정 인계

검사가 완료된 정상 PCB 수를 기준으로 제품 BOM의 부품 소요량을 계산합니다.

```
정상 PCB 수 × 모델별 BOM 수량 = 필요 자재 수량
```

현재 재고와 필요 수량을 비교하여 다음을 판정합니다.

- 진행 가능
- 진행 불가
- 추가 필요 수량
- 안전재고 미달 여부

재고가 충분한 경우에만 SMD 인계가 가능합니다. 인계 시 하나의 DB 트랜잭션에서:

- 관련 부품 행 잠금
- 최신 재고 재검증
- 재고 차감
- 자재 소비 이력 저장
- SMD 인계 시각 기록

을 수행합니다. 따라서 여러 배치가 동시에 같은 부품을 사용하더라도 재고가 음수가 되는 문제를 방지합니다.

# 4. 화면별 주요 기능

## 화면 1. 통합 대시보드

시스템 전체 현황을 한 화면에서 확인하는 메인 화면입니다.

주요 기능:

- 금일 검사 PCB 수
- 불량률
- AI 판정 수용률
- 검수 완료 객체 수
- 검사계획부터 검수까지의 Batch 파이프라인
- 계획 대비 배치 등록률
- 금일 배치 완료율
- 검사 대기 및 검수 대기 PCB 수
- 주요 불량 유형 순위
- 라인 가동·대기·정지 현황
- AGV 이동·대기·배터리 현황
- 재고 부족 경고
- 재고관리 화면 바로가기

발표 설명:
> 대시보드는 관리자에게 생산, 검사, 물류, 재고, 품질 정보를 통합해서 제공합니다. 단순한 통계 화면이 아니라 각 업무 단계의 병목 구간을 빠르게 파악할 수 있도록 구성했습니다.

## 화면 2. 검사등록

검사계획과 입고 배치를 등록하는 화면입니다.

### ① 검사계획

- 월간 달력 기반 계획 확인
- 날짜 클릭으로 검사계획 등록
- 검사 수량 설정
- PCB 모델 선택
- 검사 라인 선택
- 계획 상세 확인
- 계획 수정 및 취소
- 과거 날짜 등록 제한
- 상태별 계획 표시

### ② 입고 배치 등록

- 계획 검색 및 페이지 이동
- 계획을 기준으로 입고 배치 생성
- 배치 코드, 모델, 라인, 수량 확인
- 배치 상태 확인
- 검사 전 대기 배치 수정·취소
- 선택 배치를 불량검사 화면에서 바로 열기

발표 설명:
> 검사계획과 실제 입고 배치를 분리했습니다. 계획은 언제, 어떤 모델을, 몇 개 검사할지를 정의하고, 배치는 실제 검사 대상 PCB와 이미지를 묶은 실행 단위입니다.

## 화면 3. 불량검사 – 실시간 검사

AI 검사를 실행하고 진행 상태를 실시간으로 확인하는 화면입니다.

주요 기능:

- 배치 카드 조회
- 날짜·라인·상태별 필터
- 배치 검사 준비 여부 확인
- 검사 시작
- WebSocket 연결 상태 표시
- PCB 이미지 캐러셀
- 현재 PCB 선택 및 순번 확인
- 전체 검사 진행률
- 정상·불량 상태
- Detection별 불량 유형·신뢰도
- Bounding Box 결과 확인
- 검사 중 PCB 이동 잠금
- 오류 및 재연결 상태 안내

발표 설명:
> 사용자는 배치를 선택하고 검사 시작 버튼을 누릅니다. 백엔드는 PCB를 순차적으로 YOLO에 전달하고, 결과를 저장한 뒤 WebSocket으로 진행 상황을 전송합니다. 따라서 페이지를 새로고침하지 않아도 현재 검사 위치와 판정 결과를 확인할 수 있습니다.

---

## 화면 4. 불량검사 – 검사 결과 및 검수

AI 판정을 작업자가 최종 확인하는 Human-in-the-loop 화면입니다.

주요 기능:

- 검사 완료 배치 목록
- 라인·불량 여부·날짜·정렬 필터
- NG PCB 검수 대기열
- PCB 원본 이미지 확인
- Bounding Box 표시 전환
- 이미지 확대·축소 및 이동
- Detection별 불량 유형과 신뢰도 확인
- AI 판정 승인
- 불량 유형 수정
- 오탐 처리
- 일괄 승인
- 검수 완료·대기 수량 확인
- 이전·다음 검수 대상 이동

# 5. 데이터베이스 설계

## 핵심 데이터 관계

```
product_model
    └─ bom_item ─ part

production_plan
    └─ production_batch
          ├─ batched_pcb ─ original_pcb
          │      └─ inspection_result
          │              └─ defect_review
          ├─ post_inspection_buffer_slot
          └─ batch_material_consumption

line
 ├─ production_plan
 ├─ production_batch
 ├─ sensor_data
 └─ agv
```

## 주요 테이블

| 테이블 | 역할 |
|---|---|
| production_plan | 검사계획 |
| production_batch | 입고 PCB 검사 배치 |
| original_pcb | 원본 PCB 이미지 메타데이터 |
| batched_pcb | 배치에 편성된 개별 PCB |
| inspection_result | YOLO 검사 및 Detection 결과 |
| defect_review | 작업자 최종 판정 |
| line | 검사 라인 |
| agv | AGV 상태 |
| post_inspection_buffer_slot | 검사 후 버퍼 슬롯 |
| product_model | PCB 제품 모델 |
| bom_item | 모델별 BOM |
| part | 부품 재고 |
| batch_material_consumption | 배치별 자재 소비 이력 |
| sensor_data | 센서 측정 데이터 |
| alarm, alarm_threshold | 경보 기준 및 발생 이력 |
| report_history | 분석 리포트 생성 이력 |

## 설계 핵심

- 계획, 배치, PCB, Detection을 분리해 추적성 확보
- 하나의 PCB에서 여러 불량이 검출될 수 있도록 Detection 단위 저장
- AI 원본 판정과 작업자 최종 판정을 별도로 보존
- DB 트랜잭션과 행 잠금으로 동시 처리 충돌 방지
- 스키마 변경은 migration 파일로 관리
- 실제 이미지 경로 대신 데이터셋 기준 상대 경로 저장
- 검사·판정·물류·재고 이력을 삭제하지 않고 상태로 관리

# 7. 실시간 통신 설계

프로젝트는 목적별로 WebSocket을 분리했습니다.

| 채널 | 역할 |
|---|---|
| /ws | 계획·배치·판정·재고 인계 이벤트 |
| /ws/inspections | PCB별 검사 진행 및 완료 이벤트 |
| /ws/process-status | AGV 이송·라인·버퍼 이벤트 |

REST API는 현재 상태 조회와 명령 실행에 사용하고, WebSocket은 상태 변경 알림에 사용합니다.

```
REST: 현재 상태를 정확하게 조회
WebSocket: 변화가 발생했음을 실시간 전달
재연결 시: REST로 최신 상태 재동기화
```

이 방식은 WebSocket 메시지가 누락되거나 브라우저가 잠시 연결을 잃어도 서버의 최종 상태를 다시 복원할 수 있다는 장점이 있습니다.

# 9. 프로젝트의 차별점

## 1. 단순 AI 데모가 아닌 전체 업무 흐름

이미지를 업로드하고 결과만 보여주는 데서 끝나지 않고 다음 공정을 연결했습니다.

```
계획 → 배치 → AI 검사 → 사람 검수 → AGV → 재고 → 분석
```

## 2. Human-in-the-loop

AI의 결과를 최종 정답으로 취급하지 않고 작업자의 승인·수정·오탐 판정을 별도로 저장합니다.

이를 통해:

- AI 오판 방지
- 실제 품질 판정의 신뢰성 확보
- 재학습 데이터 축적
- 모델 성능 추적

이 가능합니다.

## 3. 작은 불량 검출을 위한 타일 추론

고해상도 PCB 전체를 단순 축소하지 않고 3×3으로 분할해 추론함으로써 작은 결함의 특징 손실을 줄였습니다.

## 4. 상태 기반 AGV 연계

AGV 애니메이션만 보여주는 것이 아니라 배치 상태, 물류 위치, 버퍼 슬롯, 라인 점유를 연결했습니다.

## 5. 품질 데이터의 재활용

검사 결과를 대시보드, 검수, 재고 판단, Pareto 분석, 히트맵, 리포트, 챗봇에서 공통으로 사용합니다.

# 11. 발표 마무리 멘트

> 저희 프로젝트는 AI 모델의 불량 검출 정확도만 보여주는 시스템이 아닙니다. 검사계획 등록부터 배치 구성, AI 검사, 작업자 최종 검수, AGV 이송, 재고관리, 품질 분석까지 제조 현장의 전체 데이터 흐름을 하나의 MES로 연결했습니다.
>
> 특히 AI의 판정과 작업자의 최종 판정을 분리해 신뢰성을 확보했고, 그 결과를 다시 분석과 모델 재학습 판단에 활용할 수 있도록 설계했습니다. 이를 통해 품질검사의 자동화뿐만 아니라 공정 운영의 가시성과 데이터 기반 의사결정까지 지원하는 것이 본 프로젝트의 핵심입니다.

# 12. 한계점과 향후 발전 방향

현재 발표에서 반드시 구분해서 설명해야 할 부분입니다.

## 현재 한계

- AGV는 실제 하드웨어 제어가 아닌 상태전이 시뮬레이션
- 센서 테이블과 수집 구조는 있으나 화면 일부 수치는 시뮬레이션
- 실제 운영용 인증·사용자 권한 관리 미구현
- YOLO 검사에는 외부 모델 가중치와 PCB 데이터셋 필요
- 검사 작업 상태 일부가 서버 메모리에 있어 다중 서버 운영 시 별도 작업 큐 필요
- 작업자 최종 판정 잠금 후 관리자 재개방 기능 없음
- 챗봇 실시간 데이터 조회 범위가 Dashboard와 Batch 중심으로 제한됨

## 향후 발전 방향

- 실제 AGV 관제 시스템 및 PLC/MQTT 연동
- 카메라 실시간 촬영 스트림 연동
- 온도·습도·진동·먼지 센서 실데이터 수집
- Redis/Celery 기반 분산 검사 작업 처리
- 사용자 인증 및 역할별 권한 관리
- 작업자 수정 데이터 기반 YOLO 재학습 파이프라인
- RAG 기반 MES 지식 검색
- 설비 예지보전 및 불량 원인 상관관계 분석
- 운영 모니터링·로그·알림 시스템 추가
- 오브젝트 스토리지 기반 이미지 관리
