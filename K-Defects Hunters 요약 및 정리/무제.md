## 오늘(8/13) 진행 순서 및 완료된 것

1. **환경 전환**: 데스크탑에 `git clone` → `dev` 체크아웃 → `credential.helper store` 설정
2. **서버 생존 확인**: `curl http://3.38.222.241/health/ready` → `{"status":"ok"}` 확인 (어제 배포 그대로 살아있음)
3. **DB 데이터 현황 확인**: `line` 8개, `product_model` 10개만 있고 나머지 15개 테이블(배치/검사/재고 등)은 전부 0건. 정상적인 상태로 판단, 앞으로 실사용하며 데이터 쌓을 예정
4. **ufw 방화벽 이중 방어 적용 완료** (22/80/443만 허용)
5. **SSH 키 발급 실수 → 재발급 완료**
   - GitHub **Repository Variables**(평문 노출)에 `SSH_HOST`, `SSH_PRIVATE_KEY`, `SSH_USER`를 잘못 등록했던 걸 발견
   - Variables 삭제, 새 키(`pcb-mes-prod-deploy-v2`) 발급, 서버 `authorized_keys`를 v2로 완전 교체(구 키는 `Permission denied`로 무효화 확인됨), **Secrets 탭**(암호화)에 v2로 재등록 완료
   - 로컬에 SSH 키 파일 4개가 프로젝트 폴더에 그대로 있음(`pcb-mes-prod-deploy`, `pcb-mes-prod-deploy.pub`, `pcb-mes-prod-deploy-v2`, `pcb-mes-prod-deploy-v2.pub`) — **아직 `.gitignore` 처리 안 함, 실수로 커밋 안 되게 주의 필요**
6. **`deploy.yml` 작성 및 push**
   - Codex로 작성 → 처음엔 "생성했다"고 보고했지만 실제로는 저장 안 된 것으로 확인되어 재작성
   - 재작성 후 실제로는 **로컬 바깥쪽 폴더**(`pcb-defects-mes\.github\workflows\deploy.yml`)에 저장된 것을 발견 → `move` 명령으로 안쪽 폴더로 이동
   - `git add`/`commit`/`push` 진행 중 `Repository not found` 인증 오류 발생 → `.git-credentials` 파일 자체가 없던 것으로 확인 → 재시도 후 정상 push 성공 (`704f1a9`)
   - GitHub 웹 파일 뷰(`blob/dev/.github/workflows/deploy.yml`)에서 파일 내용, 위치, 커밋 전부 **정상 확인됨**

## ❗ 지금 안 풀리고 있는 문제 — Actions에서 Deploy 워크플로우가 인식 안 됨

**핵심 증상**: `deploy.yml`이 GitHub 저장소의 정확한 경로(`dev` 브랜치, `.github/workflows/deploy.yml`)에 정상적으로 존재하고 커밋도 완료됐는데(`704f1a9`, 이후 재커밋 `084922b`까지 push함), **Actions 탭 좌측 워크플로우 목록에 "Deploy"가 전혀 나타나지 않는다.**

[https://github.com/KDTbigdata8th/pcb-defects-mes/actions/workflows/deploy.yml](https://github.com/KDTbigdata8th/pcb-defects-mes/actions/workflows/deploy.yml)  
→ "Not found" / "This workflow does not exist." / "0 workflow runs"

좌측 목록에는 `All workflows`, `CI`만 있고 `Deploy`가 없음.

2. **`084922b` 재커밋 이후 Actions 탭에 Deploy가 나타났는지 재확인** (마지막으로 미확인 상태로 새 채팅 넘어감)
3. 위 둘 다 정상인데도 안 되면 **GitHub 웹 에디터로 직접 새 워크플로우 파일 생성** (`Add file → Create new file`, 웹에서 직접 타이핑하여 인코딩 문제 원천 차단)
4. **저장소 Default Branch가 여전히 `main`인 상태** — 이것도 워크플로우 인식에 영향 줄 가능성 완전 배제 못함(원인 후보로 낮지만 열어둘 것). Default branch를 `dev`로 바꾸는 건 Admin 권한 필요, 아직 요청만 해둔 상태(미해결)
5. Codex한테 확인 요청하지 말고, **사용자가 직접 `cd` 해서 안쪽 폴더 기준으로 명령어 실행**하며 진행할 것
