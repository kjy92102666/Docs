# 4-1. AWS 운영 DB 스키마 읽기 전용 실태조사

현재까지 migration 전수조사를 완료했습니다.

중요하게 확인된 사실:

- backend/db/migrations는 forward-only migration 체계가 아님
    
- destructive migration, rollback/reference, duplicate/obsolete migration이 섞여 있음
    
- migrations/*.sql 전체 자동 실행은 금지
    
- 최신 schema.sql에는 대부분의 최신 구조가 반영되어 있음
    
- 다만 post_inspection_buffer_slot의 1~16 초기 슬롯 데이터는 schema.sql에 없음
    
- 현재 migration history 테이블도 없음
    

따라서 아직 deploy.yml 수정이나 migration 자동화 구현을 하지 말고, AWS 운영 DB의 실제 상태를 읽기 전용으로 조사해주세요.

## 8. BUFFER 기준 데이터 확인

다음을 읽기 전용으로 확인해주세요.

```sql
SELECT
    COUNT(*) AS slot_count,
    MIN(slot_no) AS min_slot,
    MAX(slot_no) AS max_slot,
    GROUP_CONCAT(slot_no ORDER BY slot_no) AS slots
FROM post_inspection_buffer_slot;
```

기대 상태:

```text
slot_count = 16
min_slot = 1
max_slot = 16
slots = 1,2,3,...,16
```

추가로 현재 슬롯 상태 분포도 읽기 전용으로 확인해주세요.

예:

```sql
SELECT status, COUNT(*)
FROM post_inspection_buffer_slot
GROUP BY status;
```

데이터를 수정하거나 EMPTY로 초기화하지 마세요.

## 9. migration 결과별 상태표 작성

각 migration을 아래 4가지 중 하나로 판정해주세요.

- APPLIED_EQUIVALENT
    
    - 해당 migration이 만들려고 했던 구조가 현재 DB에 존재
        
- PARTIALLY_APPLIED
    
    - 일부 구조만 존재
        
- NOT_APPLIED
    
    - 필요한 구조가 없음
        
- DO_NOT_APPLY
    
    - rollback / destructive / obsolete / 정책 충돌 때문에 자동 실행 대상이 아님
        

대상:

- 20260725_add_batch_cancelled_status.sql
    
- 20260725_add_pcb_original_master.sql
    
- 20260726_add_smd_bom.sql
    
- 20260804_add_inspection_detection_bbox.sql
    
- 20260805_add_defect_review_corrected_type.sql
    
- 20260806_add_process_status_lifecycle.sql
    
- 20260806_add_process_status_lifecycle_rollback_reference.sql
    
- 20260806_add_yolo_inspection_columns.sql
    
- 20260806_update_agv_payload_comment.sql
    
- 20260808_add_inventory_handoff.sql
    
- 20260808_add_normal_pcb_count.sql
    

중요:

"migration 파일을 실행했다"라고 추정하지 말고,  
현재 DB 객체 상태가 해당 migration 결과와 동등한지 여부만 판단해주세요.
