## 백엔드 계층별 역할

### `main.py`

`main.py`는 애플리케이션을 조립하는 역할만 담당합니다.

```
app = FastAPI()

app.include_router(planning_router)
app.include_router(batch_router)
app.include_router(inspection_router)
```

다음 내용은 `main.py`에서 분리합니다.

- Pydantic 모델
- SQL
- 생산계획 생성 로직
- 배치 생성 로직
- 검사 및 판정 로직
- WebSocket 연결 관리자

### `router.py`

HTTP 요청과 응답만 담당합니다.

- URL 정의
- Path/query/body 입력 수신
- Pydantic 검증
- Service 호출
- HTTP status code 반환

SQL을 직접 실행하지 않습니다.

### `schemas.py`

FastAPI `/docs`에 표시되는 요청·응답 스키마를 정의합니다.

```
PlanCreateRequest
PlanResponse
BatchCreateResponse
InspectionResultResponse
```

AGENTS.md 규칙에 따라 API를 변경할 때 스키마를 먼저 정의합니다.

### `service.py`

업무 흐름과 상태전이를 담당합니다.

예:

```
생산계획 검증
→ 배치 생성
→ PCB 생성
→ WebSocket 이벤트 발행
```

또는:

```
배치 readiness 확인
→ Vision 검사 실행
→ 검사 결과 저장
→ 불량 검토 항목 생성
```

### `repository.py`

DB 접근만 담당합니다.

- SELECT
- INSERT
- UPDATE
- DELETE
- DB 결과 반환

HTTP 예외나 화면 표시 문구는 처리하지 않습니다.

## 프론트엔드 구조 핵심

프론트엔드는 세 영역으로 구분합니다.

```
api      = 통신 기반
domains  = 여러 화면이 공유하는 업무 데이터
features = 실제 화면과 화면 전용 UI
shared   = 업무와 무관한 공용 UI
```

### `api/`

HTTP와 WebSocket의 기술적인 공통 처리만 둡니다.

```
api/client.js
api/websocket.js
```

현재 `api.js`의 `request()`, `API_BASE`, `WS_URL`이 이곳으로 이동합니다.

### `domains/`

여러 화면이 공유하는 API와 규칙을 둡니다.

예를 들어 `batch`는 생산계획과 PCB 검사 화면이 모두 사용합니다.

```
domains/batch/
├── batchApi.js
├── batchMapper.js
└── batchRules.js
```

`batchApi.js`에는 다음 기능이 들어갑니다.

```
listBatches
listBatchPage
createBatch
cancelBatch
listBatchPcbs
```

검사 실행은 배치 API가 아니라 검사 API에 둡니다.

```
domains/inspection/inspectionApi.js
├── listBatchInspections
└── runInspection
```

불량 판정은 review로 분리합니다.

```
domains/review/reviewApi.js
├── listBatchReviews
├── listReviews
└── decideReview
```

### `features/`

화면과 그 화면에서만 사용하는 컴포넌트·상태 로직을 둡니다.

```
features/pcb-inspection/
├── PcbInspection.jsx
├── components/
└── model/
```

`PcbInspection.jsx`는 전체 화면 상태와 작업 흐름을 관리하고, 세부 UI는 Panel과 Feature 컴포넌트로 분리합니다.

### `shared/`

특정 도메인에 속하지 않는 코드만 둡니다.

적합한 예:

- Pagination
- ErrorPanel
- LoadingPanel
- 날짜 포맷
- 숫자 포맷

부적합한 예:

- BatchManagementPanel
- InventoryTable
- InspectionAiViewer

이 컴포넌트들은 각 기능 폴더에 있어야 합니다.

## `batchService` 최종 위치

현재 소스 기준으로 배치 기능은 생산계획과 검사에서 공유하므로 검사 기능 내부에 두면 안 됩니다.

권장 위치:

```
frontend/src/domains/batch/batchApi.js
frontend/src/domains/batch/batchMapper.js
frontend/src/domains/batch/batchRules.js
```

단순 HTTP 호출만 처리한다면 `batchService.js`보다 `batchApi.js`가 정확합니다.

다음과 같이 여러 작업을 조합하는 로직이 생길 때만 추가합니다.

```
frontend/src/domains/batch/batchService.js
```

예:

```
배치 생성
→ 생성된 PCB 목록 조회
→ readiness 정보 변환
→ 화면에서 사용할 결과 반환
```

따라서 초기에는 다음 정도만 두는 것을 권장합니다.

```
domains/batch/
├── batchApi.js
├── batchMapper.js
└── batchRules.js
```

## 향후 기능 설계 방향

### 재고관리

- `inventory` 독립 도메인으로 관리
- BOM, 현재 재고, 안전재고 조회
- 부족 자재 필터링
- 생산계획에서 필요하면 `inventoryApi`를 사용
- 배치 도메인 안에 포함하지 않음

### 리포트 생성

- 프론트가 생산·검사·센서 API를 직접 모두 조합하지 않음
- 백엔드 `report` 기능이 조회·집계·파일 생성을 담당
- `report_history`에 생성 이력 저장
- 프론트는 필터 입력, 생성 요청, 다운로드, 이력 표시 담당

### 대시보드

- 여러 도메인의 원본 API를 프론트에서 각각 호출하지 않음
- 백엔드에 대시보드 집계 API 구성
- 생산, 검사, 재고, AGV 요약을 한 응답으로 제공
- WebSocket은 실시간 이벤트만 별도로 수신

예상 API:

```
GET /api/dashboard/summary
WS  /ws
```

### 챗봇

- OpenAI API와 LangChain은 백엔드에서만 사용
- API 키는 환경변수 참조
- 프론트 `ChatbotWidget`은 백엔드 챗봇 API만 호출
- 챗봇이 DB에 접근해야 한다면 repository/service를 통해 조회
- 프론트에서 SQL이나 각 업무 API를 직접 조합하지 않음

## 점진적 이전 순서

현재 코드를 한 PR에서 전부 옮기면 충돌과 테스트 수정량이 너무 커집니다. 다음 순서가 안전합니다.

1. 공통 `api/client.js` 분리
2. 프론트 `domains/batch` 분리
3. 프론트 `domains/plan`, `inspection`, `review` 분리
4. `PcbInspection.jsx` 컴포넌트 분리
5. `ProductionPlan.jsx` 컴포넌트 및 모델 정리
6. 백엔드 inspection Router/Schema 분리
7. inspection Service/Repository 분리
8. batch 기능 분리
9. planning 기능 분리
10. 기존 테스트 patch 경로 수정
11. 재고관리 기능 추가
12. 대시보드 집계 기능 추가
13. 리포트 생성 기능 추가
14. 챗봇 기능 추가

DB 변경이 포함되는 작업은 항상 다음 순서로 병합합니다.

```
DB 마이그레이션
→ 백엔드
→ 프론트엔드
```

## 팀 소유권 권장

| 경로                                | 담당             |
| --------------------------------- | -------------- |
| `backend/app/main.py`             | 백엔드 통합 담당      |
| `backend/app/core/`               | 백엔드 공용 담당      |
| `backend/app/features/<domain>`   | 해당 기능 담당       |
| `backend/db/`                     | DB 담당          |
| `backend/vision/`                 | Vision 담당      |
| `frontend/src/app/`               | 프론트 통합 담당      |
| `frontend/src/api/`               | 프론트 공용 API 담당  |
| `frontend/src/domains/<domain>`   | 해당 도메인 담당      |
| `frontend/src/features/<feature>` | 해당 화면 담당       |
| `frontend/src/shared/`            | 프론트 공용 컴포넌트 담당 |
