정확히는 **배치 생성 정책은 유지**되고, 배치가 사용할 원본 이미지를 찾고 저장하는 방식이 변경된 것입니다.

## 유지된 배치 생성 로직

다음 로직은 기존과 동일합니다.

- 생산계획의 `planned_quantity`만큼 PCB 생성
    
- 모델의 `board_no`에 맞는 PCB 이미지만 사용
    
- 배치마다 `random_seed` 생성
    
- 목표 불량률을 0~5% 사이에서 임의 생성
    
- 목표 불량률에 따라 정상 또는 불량 원본 선택
    
- 생성한 PCB마다 `true_is_defect`, `true_defect_type` 저장
    
- `production_batch`, `batched_pcb` 생성
    
- 생산계획 상태를 `BATCH_CREATED`로 변경
    

따라서 **생산계획 → 배치 등록**이라는 업무 로직이 새롭게 바뀐 것은 아닙니다.

## 실제로 변경된 부분

### 기존 방식

배치를 생성할 때 로컬 데이터셋 폴더를 직접 스캔했습니다.

```
PCB_DATASET_PATH 폴더 스캔
→ 모델 board_no에 해당하는 정상·불량 파일 목록 생성
→ 이미지 하나 선택
→ batched_pcb.image_path에 상대 경로 저장
```

즉, 이미지 후보 목록을 매번 파일 시스템에서 만들었습니다.

### 현재 방식

이미지 후보 목록을 `original_pcb` DB에서 조회합니다.

```
product_model.board_no
→ original_pcb에서 해당 보드의 정상·불량 후보 조회
→ pcb_no 선택
→ batched_pcb.pcb_no에 저장
```

실제 이미지 파일을 읽을 때는 다음 순서로 처리합니다.

```
batched_pcb.pcb_no
→ original_pcb.image_key
→ PCB_DATASET_PATH / image_key
→ Google Drive 마운트 파일 읽기
```

이 변경은 다음 위치에 반영되어 있습니다.

- `backend/app/main.py:367`
    
- `backend/app/dataset.py:27`
    

## “구글 드라이브 주소 참조”의 정확한 의미

여기서 한 가지 기술적으로 구분해야 합니다.

현재 구현은 Google Drive의 공유 URL이나 파일 ID를 직접 참조하는 방식이 아닙니다.  
Google Drive for Desktop으로 동기화된 드라이브를 일반 디스크처럼 마운트하고, 환경변수 `PCB_DATASET_PATH`에 해당 경로를 지정하는 방식입니다.

예:

```
PCB_DATASET_PATH=G:/내 드라이브/공유 폴더/Kaggle/PCB_DATASET_DATA
```

DB에는 전체 PC 경로나 Google Drive URL이 아니라 **상대 키**만 저장됩니다.

```
original_pcb.image_key
= images/Short/04_short_07.jpg
```

실제 파일 경로는 실행 시 다음과 같이 조합됩니다.

```
G:/내 드라이브/공유 폴더/Kaggle/PCB_DATASET_DATA
+ images/Short/04_short_07.jpg
```

따라서 정확한 표현은 다음과 같습니다.

> 이미지 파일은 Google Drive 마운트에 두고, DB에는 해당 이미지의 상대 경로인 `image_key`만 저장해 참조한다.

## 변경 목적

이 구조로 바꾼 주된 이유는 다음과 같습니다.

- 약 954MB의 이미지 데이터셋을 Git이나 DB dump에 포함하지 않음
    
- 팀원마다 Google Drive 마운트 경로만 `.env`에 설정
    
- 배치 생성 때마다 Google Drive 폴더 전체를 스캔하지 않음
    
- 이미지 목록과 메타데이터는 `original_pcb`가 관리
    
- 동일 이미지를 여러 배치 PCB가 사용해도 경로를 반복 저장하지 않음
    

즉, 다음과 같은 구조입니다.

```
이미지 실물
→ Google Drive

이미지 목록 및 상대 경로
→ original_pcb DB

배치와 원본 이미지 연결
→ batched_pcb.pcb_no FK
```

## AI 추론에서 달라지는 부분

AI 추론 정책도 본질적으로 달라지지 않습니다.  
이미지 획득 경로만 다음 구조에 맞춰 처리하면 됩니다.

```
pcb_id
→ batched_pcb.pcb_no
→ original_pcb.image_key
→ Google Drive 마운트 경로의 이미지 파일
→ YOLO 추론
```

`BOM`과 `Part` 추가는 AI 추론과 직접적인 관련이 없습니다.

- `BOM`: 생산 모델별 필요 자재 관리
    
- `Part`: 개별 자재 정보 관리
    
- `Vision`: `original_pcb.image_key`를 이용해 이미지 파일 조회
    

## 최종 정리

- **배치 생성 업무 로직:** 거의 그대로 유지
    
- **불량률 및 정상·불량 추출 방식:** 유지
    
- **이미지 후보 조회:** 폴더 스캔 → `original_pcb` DB 조회
    
- **배치의 이미지 연결:** `image_path` 직접 저장 → `pcb_no` FK 저장
    
- **이미지 실물:** Google Drive for Desktop 마운트에서 읽음
    
- **Google Drive 공유 URL/API 직접 접근:** 사용하지 않음
    
- **BOM/Part:** 별도 자재 관리 기능이며 현재 배치 생성에는 아직 연결되지 않음
