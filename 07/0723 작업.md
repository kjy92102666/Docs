- 정상 이미지 재사용 허용, PCB별 할당은 생성 시 고정
- 재검사 시 저장된 이미지 사용 구조 유지
- `GET /api/pcb/{pcb_id}/image` 추가
- 배치 목록에 `pcb_count`, `image_linked_count`, `inspection_ready` 추가
- 이미지 누락 배치는 검사 시작 차단
- 추후 서버 스토리지로 이전해도 DB 상대 키를 그대로 사용 가능
- 실제 데이터셋 확인: 정상 10장, 불량 693장

```
# 재고 연동

이 프로젝트에서 재고는 단순 수량보다 PCB별 상태로 관리하는 것이 좋습니다.

## PCB 재고 상태

```
RECEIVED
→ 공장에 입고되어 검사 대기 중

READY_FOR_INSPECTION
→ 이미지 연결과 검사 준비 완료

IN_INSPECTION
→ 현재 검사 중

PASS_PENDING
→ AI가 정상으로 판단했지만 검사 작업 완료 전

DEFECT_PENDING
→ AI가 불량 후보로 판단하여 작업자 확인 대기

PASSED
→ 최종 정상 확정

QUARANTINED
→ 최종 불량 확정, 격리 대상

REWORK
→ 재작업 대상

SCRAPPED
→ 폐기 대상
```

## 단계별 재고 처리

### 검사계획 등록

아직 입고 PCB를 특정하지 않았으므로 재고를 변경하지 않습니다.

```
계획 수량: 500
실제 입고 PCB: 아직 연결 안 됨
```

### 입고 배치 등록

배치에 PCB 500개를 등록하면서 각 PCB를 입고 재고로 만듭니다.

```
PCB-00001 → RECEIVED
PCB-00002 → RECEIVED
...
PCB-00500 → RECEIVED
```

### 이미지 연결 완료

모든 PCB에 이미지가 연결되면 검사 대기 상태로 변경합니다.

```
RECEIVED → READY_FOR_INSPECTION
```

### 검사 시작

선택 배치의 PCB 상태를 검사 중으로 변경합니다.

```
READY_FOR_INSPECTION → IN_INSPECTION
```

### AI 판정

YOLO 결과에 따라 임시 상태를 설정합니다.

```
AI 정상
→ PASS_PENDING

AI 불량
→ DEFECT_PENDING
```

AI 불량을 곧바로 최종 불량 재고로 처리하지 않는 것이 중요합니다. 오탐일 가능성이 있기 때문입니다.

### 작업자 최종 판정

```
AI 정상 또는 오탐 처리
→ PASSED

불량 확정
→ QUARANTINED

재작업 결정
→ REWORK

폐기 결정
→ SCRAPPED
```

현재 AGV는 상태전이 시뮬레이션이므로 `QUARANTINED`로 확정된 PCB에 대해서만 AGV 호출 상태를 만들면 됩니다.

## 재고 수량 계산

별도의 숫자만 저장하기보다 PCB 상태를 집계하는 방식을 추천합니다.

```
SELECT status, COUNT(*)
FROM pcb
WHERE batch_id = ?
GROUP BY status;
```

예:

```
입고: 500
검사 중: 0
정상 완료: 487
불량 확인 대기: 8
격리: 5
```

이렇게 하면 개별 PCB 상태와 화면의 재고 수량이 어긋나는 문제를 줄일 수 있습니다.

```
