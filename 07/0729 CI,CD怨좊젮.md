이 프로젝트는 **바로 CI 파일부터 만드는 것보다, 먼저 "무엇을 정상 상태로 판단할 것인지"를 정의하는 것이 중요합니다.**

# 1. Git 상태부터 안전하게 복구

현재 로컬 `.git` 폴더가 비어 있어 정상적인 Git 저장소가 아닙니다.

이 상태에서 바로

```bash
git init
git add .
git push
```

를 수행하면 원격 저장소와 충돌하거나 기존 이력을 덮어쓸 가능성이 있습니다.

### 권장 방법

```text
원격 저장소 Clone
        ↓
main/dev 구조 확인
        ↓
현재 로컬 소스와 비교
        ↓
최신 파일만 복사
        ↓
dev 브랜치 Commit
        ↓
Pull Request
        ↓
main 병합
```

처럼 상대 경로를 사용할 경우 CI에서는 실행 위치가 달라 실패할 수 있습니다.

# DB SQL 파일 용도 정리

## 각 파일의 역할

| 파일                                        | 용도                                           | 기존 데이터 영향                     |
| ----------------------------------------- | -------------------------------------------- | ----------------------------- |
| `20260725_add_batch_cancelled_status.sql` | `production_batch.status`에 `CANCELLED` 상태 추가 | 기존 배치 데이터 유지                  |
| `20260725_add_pcb_original_master.sql`    | `original_pcb` 테이블 생성 및 `batched_pcb` 구조 변경  | 기존 검사·배치 데이터 삭제 가능            |
| `20260726_add_smd_bom.sql`                | `part`, `bom_item` 테이블 생성                    | 테이블만 생성, 기존 데이터 삭제 없음         |
| `pcb_seed.sql`                            | `original_pcb` 샘플 데이터 입력                     | `original_pcb` 전체 삭제 후 재입력    |
| `bom_seed.sql`                            | `part`, `bom_item` 샘플 데이터 입력                 | 두 테이블 전체 삭제 후 재입력             |
| `schema.sql`                              | 신규 DB 초기 생성용 전체 스키마                          | 기존 DB에서 재실행 시 충돌 가능           |
| `pcb_mes_dump.sql`                        | DB 전체 백업 및 복원                                | `pcb_mes` 데이터베이스를 삭제 후 재생성 가능 |

---

## `bom_seed.sql`이 기존 데이터를 삭제하는 이유

테스트 데이터를 항상 동일한 상태로 재현하기 위해 기존 데이터를 초기화한 후 다시 입력합니다.

실행 순서는 다음과 같습니다.

1. **`bom_item` 삭제**

   * `part`를 참조하는 자식 테이블이므로 먼저 삭제

2. **`part` 삭제**

   * 기존 데이터와 Seed 데이터가 중복되지 않도록 초기화

3. **AUTO_INCREMENT(ID) 초기화**

4. **`part` → `bom_item` 순서로 재입력**

   * 외래 키(Foreign Key) 관계를 만족시키기 위한 순서

## 개발 중 권장 사용 방법

### Migration 파일

다음 파일들은 **각각 한 번만 실행**합니다.

* `20260725_add_batch_cancelled_status.sql`
* `20260725_add_pcb_original_master.sql`
* `20260726_add_smd_bom.sql`

### Seed 파일

다음 파일들은 **초기 개발 환경 구축** 또는 **테스트 데이터 전체 초기화**가 필요한 경우에만 실행합니다.

* `pcb_seed.sql`
* `bom_seed.sql`

이후에는 기존 데이터를 삭제하지 않는 **별도의 INSERT/UPSERT SQL**을 사용하는 것을 권장합니다.

## 현재 DB 상태

현재 적용된 최신 `pcb_mes_dump.sql`에는 다음 내용이 이미 포함되어 있습니다.

* 15개 전체 테이블
* BOM 관련 테이블
* BOM 샘플 데이터

따라서 현재 DB에서는 아래 파일을 **다시 실행하면 안 됩니다.**

* ❌ `20260726_add_smd_bom.sql`
* ❌ `bom_seed.sql`

중복 실행 시 테이블 생성 충돌 또는 데이터 초기화가 발생할 수 있습니다.
