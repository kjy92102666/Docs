## 🚀 2. 학습 완료 후 결과물로 하게 될 일

학습이 끝나면 구글 드라이브의 `PCB_yolo_result/pcb_test_run/weights/` 경로에 **`best.pt`** (약 6MB 크기의 모델 파일)가 생성됩니다.

이 `best.pt` 파일과 연습한 결과로 다음 3가지 핵심 작업을 진행하게 됩니다.

### ① Colab에서 추론(Inference) 결과 확인

- 검증용 PCB 이미지(`val`)를 입력했을 때 AI가 **어떤 유형의 불량을 발견했고, 확신도(Confidence Score)가 얼마인지** 눈으로 직접 확인합니다. (예: `Missing_hole: 0.92`)
    

### ② AI 출력 결과를 로컬 프로젝트 데이터 스펙으로 변환 연습

- AI의 Bounding Box 결과를 프로젝트 DB 데이터베이스 컬럼 형식으로 매핑하는 로직을 점검합니다:
    
    - `detected_is_defect`: `True` / `False`
        
    - `detected_defect_type`: `"MISSING_HOLE"`, `"SHORT"` 등
        
    - `confidence_score`: `0.92`
        

### ③ 로컬 백엔드 파일(`inspection_policy_practice.py`) 연동

- 로컬 작성 완료된 `inspection_policy_practice.py` 파일 내의 **`mock_yolo_infer()`** 자리에 학습한 `best.pt` 기반 추론 함수를 연결합니다.
    
- 이를 통해 "카메라/센서 스냅샷 촬영 ➔ YOLO 불량 판정 ➔ 알람/검사 결과 저장"으로 이어지는 실제 비전 검사 시스템 정책 전체를 완성/테스트하게 됩니다.



현재 백엔드 데이터베이스와 웹 UI 구조(계획 등록 ➔ 배치 선택 ➔ 비전 검사 실행)에 YOLO 추론 결과를 연결할 때, **백엔드에서 처리하고 관리해야 할 핵심 기능과 비즈니스 로직**은 크게 5가지로 나뉩니다.

실제 스마트 팩토리 MES/비전 검사 시스템의 백엔드 Architecture 관점에서 설명해 드릴게요.

### 1. 검사 결과 DB 저장 및 이력 관리 (`inspection_result`)

AI가 이미지를 받아 판정한 결과를 수신하여 DB 테이블에 영구 저장합니다.

- **저장 항목 스펙:**
    
    - `batch_id`: 현재 검사 중인 작업 배치 ID (외래키)
        
    - `inspection_time`: 검사 일시
        
    - `detected_is_defect`: 불량 여부 (`Boolean` -> `True` / `False`)
        
    - `detected_defect_type`: 불량 유형 문자열 (`NORMAL`, `MISSING_HOLE`, `SHORT`, `SPUR` 등)
        
    - `confidence_score`: AI 신뢰도 점수 (`Float`, 예: `0.92`)
        
    - `raw_image_url` / `annotated_image_url`: 원본 PCB 이미지 경로 및 AI가 바운딩 박스를 친 결과 이미지 경로
        

### 2. 검사 정책 및 임계값(Threshold) 기반 판정 로직

AI가 내놓은 `confidence_score`(확신도)를 백엔드 비즈니스 로직에서 그대로 믿을지, 아니면 필터링할지 정책 제어가 필요합니다.

- **양품/불량 자동 분류 판정:**
    
    - 예: `confidence_score`가 **0.5 미만**이면 AI가 탐지했더라도 "노이즈/오탐"으로 간주하여 `NORMAL`(양품)로 처리.
        
    - 예: `confidence_score`가 **0.85 이상**인 명확한 불량만 즉시 자동 불량 확정 처리.
        
- **재검사(Uncertain/Manual Check) 상태 분류:**
    
    - 신뢰도가 애매한 수치(`0.5 ~ 0.7`)인 경우 `STATUS_UNCERTAIN`(재확인 필요) 상태값으로 DB에 저장하여, 작업자가 웹 UI에서 수동으로 확인 및 승인할 수 있도록 분류합니다.
        

### 3. 배치(Batch) 상태 및 집계 수치 즉시 업데이트

검사 한 건이 수행될 때마다 해당 배치(`batch`)의 통계 정보를 실시간 갱신합니다.

- **배치 누적 수치 업데이트:**
    
    - `total_inspected_count += 1` (총 검사 수)
        
    - 불량 발생 시 `defect_count += 1` (총 불량 수), `yield_rate` (수율 = $\frac{\text{양품 수}}{\text{총 검사 수}} \times 100$) 실시간 재계산.
        
- **배치 상태 자동 전환:**
    
    - 계획된 배치 수량(예: 100개) 검사가 완료되면 배치 상태를 `IN_PROGRESS`(진행 중) ➔ `COMPLETED`(완료)로 자동 변경.
        

### 4. 웹 프론트엔드로의 실시간 알림 (Notification/Event Broadcast)

검사 화면에서 배치를 선택한 상태일 때, 비전 검사가 일어날 때마다 웹 화면이 실시간으로 변하도록 이벤트를 보냅니다.

- **WebSocket / Server-Sent Events (SSE) 연동:**
    
    - 연속 불량이 발생하거나(예: 3연속 `SHORT` 발생), 크리티컬 불량(`MISSING_HOLE`) 감지 시 백엔드에서 프론트엔드로 즉시 알림 이벤트 전송.
        
    - 웹 화면의 검사 로그 테이블 및 차트/수율 현황이 실시간 업데이트되도록 지원.
        

### 5. 통계 및 대시보드 API 데이터 집계 (Analytics)

추후 대시보드나 리포트 화면을 위해 불량 통계 데이터를 그룹화하는 API를 제공합니다.

- **불량 유형별 분포 API:** `MISSING_HOLE` 몇 건, `SHORT` 몇 건 등 불량 유형별 비중(파이 차트용 데이터).
    
- **배치별 수율/불량률 추이 API:** 등록된 배치 간의 품질 비교 통계 데이터 반환.
    

### 💡 정리: 백엔드 개발 작업 순서 추천

현재 "1. 계획 등록 ➔ 2. 배치 선택"까지 구현되어 있으므로, 백엔드 작업 흐름을 아래와 같이 이어가시면 완벽합니다!

1. **`inspection_result` DB 엔티티/테이블 설계**
    
2. **`POST /api/v1/inspections` (검사 실행 및 결과 저장 API) 구현**
    
    - 배치를 지정하고 이미지(또는 mock 결과)를 받아 AI 결과를 DB에 저장 및 배치 통계 갱신.
        
3. **`GET /api/v1/batches/{id}/results` (배치별 검사 이력 조회 API) 구현**
    
    - 웹 검사 화면에서 선택한 배치의 검사 결과 목록을 표로 불러올 수 있도록 연결.
